# 本文枠の固定と画像の切り替え

固定キット（`kit/releases/0.1.0/`）は変えず、作品側の `game.css` と `game-stage.js` で調整しています。本文・行ID・分岐・判定・作品ID・保存キー・データ版・素材・画像の表示区間は変えていません。

## 本文枠（`game.css`）

同じ画面サイズでは、背景・一枚絵・台詞か地の文か・文章量・選択肢の有無によって、本文枠・本文の読み始め・場面名の札・ページ表示・操作ボタンの位置と大きさを変えません。

- 本文枠の高さは「上下の余白（12px×2）＋話者名の行（26px）＋本文4行＋4px」で固定する。文字は17px。行間は1.8で、高さの小さい画面（高さ500px以下）だけ1.6。
- 話者名がない地の文でも話者名の行の高さを取っておき、本文の読み始めの位置をそろえる。
- 本文枠はボタン要素なので、既定では中身が上下中央に寄る。上詰めにして、短い文章も同じ位置から読み始める。
- 「タップで進む」は話者名の行の右端に置き、本文の最終行に重ねない。
- 場面名の札（高さ22px）と操作ボタンの列（高さ36px、上に8px）は高さを固定する。本文枠は操作ボタンの列と重ならない。
- 作品の全1,422行は、667×375・844×390・956×440・1280×720 で本文枠の4行以内に収まる（最長は c24-013 の125文字で、667×375 で4行）。本文の分割や行IDの変更はしていない。

| 画面 | 本文枠（左, 上, 幅, 高さ） | 本文の読み始め（上） |
|---|---|---|
| 667×375 | 16, 156, 635, 163 | 195 |
| 956×440 | 16, 221, 924, 163 | 260 |
| 1280×720 | 16, 488, 1248, 176 | 527 |

一枚絵の表示中も本文枠は通常と同じで、画像ごとに幅・高さ・位置・下地の濃さを変えない。一枚絵は全面表示のまま（`docs/cg-staging.md`）。

例外（第5便の試作）：指定した3行（`c20-004`・`c29h-012`・`c35-019`）の導入だけ、一枚絵が出た時点で本文枠（話者名・本文・「タップで進む」）と場面名の札を一時的に隠し、次の入力で同じ行の本文枠を戻す（`game-reveal.js`）。`visibility` で隠すので、枠の位置・大きさ・不透明度、操作ボタンの配置は変えず、レイアウトも動かない。詳しい操作は `docs/cg-staging.md`。

## 選択肢

選択肢は本文枠を押し上げず、場面名の札の上に、独立した領域として重ねる（場面名の札との間は10px）。最後の本文は本文枠に残ったまま読める。作品の選択肢は15か所で、すべて2択・最長20文字（「面会の案内を日和に任せ、外野の送球を見る」）。3つの画面サイズとも1行で収まる。

選択肢のボタンは本文枠の外にあるので、選択肢を押しても本文は送られず、選んだ先の最初の行で止まる。

## 画像の切り替え（`game-stage.js`）

### 黒い画面が挟まった原因

キットは行が変わるたびに、表示の更新（`updateFromState`）で次のことをしていた。

- 背景の `background-image` を次の画像の URL へすぐ書き換える。次の画像の読み込みが終わるまで背景の要素は下地の色（ほぼ黒）になる。
- 一枚絵の `src` も次の画像へすぐ書き換え、一枚絵を外すときは `src` を消す。新しい一枚絵の読み込み中は透明になり、外したときは下の背景がまだ読み込み中なら黒が見える。
- 立ち絵は同じ画像でも毎回いったん消して作り直す。新しい画像の読み込み中は人物のいない画面になる。

キャッシュのない最初の表示や、回線が遅いときほど黒い時間が長くなっていた。暗転やフェードの演出はキットにも作品にもなく、黒は読み込み待ちの空白だった。

### 修正

作品側の `game-stage.js`（`index.html` でキットの起動直後に読む）で、キットの表示の更新だけを差し替える。

1. 次の行の状態（背景・左右の立ち絵・一枚絵）で使う画像を、すべて裏で読み込んでデコードする。
2. 揃うまでは、現在の背景・立ち絵・一枚絵をそのまま残す。本文は待たずに進む。
3. 揃った時点で、キットの元の処理で一度に切り替える。フェードは入れない。読み込み済みの画像だけなら、その場で切り替える（待ち時間なし）。
4. 後から別の切り替えが始まっていたら、前の切り替えは捨てる。高速送りや既読SKIPで読み込みの順番が前後しても、古い画像は後から出ない。
5. 立ち絵は、同じ画像のままなら作り直さない。
6. 読み込みに失敗した画像は、その部分だけ現在の画像を残す。失敗した URL を `window.KIT_STAGE.errors` と console の警告（`[画像の読み込みに失敗]`）に記録する。本文の進行は止めない。
7. タイトルへ戻るとき（表示する状態がない）は、キットのまま消す。

一枚絵から通常画面へ戻るときも、戻り先の背景と立ち絵が揃うまで一枚絵を残し、揃ったら一度に切り替える。

### 残る黒

「はじめから」「つづきから」で作品画面に入った最初の行は、まだ表示している画像がないので、読み込みが終わるまで下地の色になる（タイトル画面から作品画面へ移る瞬間）。行と行の間の切り替えでは、黒は挟まらない。

## 確認方法（`tests/game/play.js`）

- **本文枠の固定**：667×375・956×440・1280×720 で全1,422行を表示し、本文枠・本文の読み始め・場面名・操作ボタンがそれぞれ一つの位置と大きさに決まること、本文が枠に収まることを確かめる。
- **選択肢**：15か所すべてで本文枠などが動かないこと、選択肢が場面名の札の上に間隔を空けて画面内に出ること、押した後に次の行へ送られないことを確かめる。
- **画像の切り替え**：キャッシュのない新しい文脈で、画像の応答を700ms遅らせ、毎フレーム（`requestAnimationFrame`）の表示を記録する。対象は次の切り替え。
  - 背景の変更
  - 通常画面と一枚絵の行き来（立ち絵2人が戻る河本の場面を含む）
  - 回想への出入り（c15-008・c15-014）

  空の背景・読み込みの終わっていない画像・一枚絵の上の立ち絵のフレームがないことと、前の画面から次の画面へ直接切り替わることを確かめる。
- **古い画像の後出し・高速送り・既読SKIP**：応答時間をばらつかせて、遅い画像の読み込み中に別の行へ移った場合、40回の高速送り、既読SKIP のそれぞれで、最後の行の画像で止まり、行の並びで後戻りしないことを確かめる。
- **読み込みの失敗**：背景の読み込みを失敗させ、前の背景が残ること、記録されること、その後も進行できることを確かめる。

## 本文の改行と表示単位

本文には、意味の区切りと読ませる順序を考えて改行（`\n`）を入れています。本文枠の大きさは変えず、文字も小さくしていません。

- 句点を改行の候補にし、読点では動作の切り替わりや間を置く箇所だけで改行する。すべての句読点で機械的に改行はしない。
- 1行に収まる短い台詞・地の文は、そのままにする。驚きやギャグの落ちは、前の説明から改行で独立させる。
- 改行後も本文枠（4行）に収まらないときだけ、意味の切れ目で表示単位を分ける。元の行IDを先頭に残し、続きは `元のID-2`、`元のID-3` とする。分割したのは c24-013 だけ（3単位）。
- 既読の判定（行ID＋本文の指紋）は空白と改行を無視するので、改行だけを入れた行は既読のまま。文言を変えた行と分割した行は未読になる。
- 全1,424行が、667×375・844×390・956×440・1280×720 で本文枠に収まることを試験で確かめる。
